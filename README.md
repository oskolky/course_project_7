# Log Analyzer

Учебный прототип системы интеллектуального анализа логов и ошибок веб-сервера. Реализован на Python в соответствии с проектной архитектурой курсовой работы.

## Возможности

- загрузка NGINX/Apache access log, error log, JSON Lines и структурированных записей API;
- нормализация к единой схеме события с сохранением исходной строки;
- диагностика повреждённых записей без остановки обработки;
- шаблонизация сообщений методом на основе наибольшей общей подпоследовательности;
- корреляция по trace ID и request ID, ограниченная эвристика при их отсутствии;
- построение временных окон и векторов признаков;
- версионируемые YAML-правила и Isolation Forest;
- независимый арбитраж результатов правил и модели;
- инциденты с доказательствами, признаками окна и состоянием ручной проверки;
- маскирование секретов, токенов, адресов электронной почты и последнего октета IPv4 в API;
- REST API, асинхронные запуски анализа, веб-интерфейс;
- SQLite по умолчанию и PostgreSQL через `DATABASE_URL`.

## Запуск

Требуется Python 3.12.

```bash
python -m pip install -r requirements.txt
python main.py
```

Откройте `http://localhost:3000`. Документация API доступна по адресу `http://localhost:3000/docs`.

Для PostgreSQL:

```bash
export DATABASE_URL='postgresql+psycopg://user:password@localhost:5432/log_analyzer'
python main.py
```

Для Docker:

```bash
docker build -t log-analyzer .
docker run --rm -p 3000:3000 -v log-analyzer-data:/app/data log-analyzer
```

## Демонстрация

Кнопка «Запустить демо» загружает связанные access/application/error logs и запускает полный анализ. В демонстрационном наборе есть рост ответов 401, массовые 404 статических ресурсов, тайм-ауты upstream с ответами 504 и одна повреждённая JSON-строка.

## Основные API-ресурсы

- `POST /api/datasets` — multipart-загрузка файлов;
- `POST /api/datasets/json` — загрузка массива структурированных записей;
- `POST /api/analysis` — новый запуск анализа существующего набора;
- `GET /api/runs/{run_id}` — состояние запуска без повторных вычислений;
- `GET /api/events` — нормализованные события;
- `GET /api/incidents` — реестр с фильтрами;
- `GET /api/incidents/{incident_id}` — карточка и доказательства;
- `GET /api/rules`, `POST /api/rules` — версии YAML-правил;
- `GET /api/models`, `POST /api/models/train` — реестр и обучение моделей;
- `GET /api/overview` — временные ряды и статистика;
- `POST /api/demo` — полный демонстрационный сценарий.

## Проверка

```bash
pytest
```

Тесты используют отдельную временную SQLite-базу и не изменяют рабочие данные. Покрыты разбор форматов, шаблонизация, корреляция, признаки, таблица арбитража, REST API и восемь сквозных сценариев из отчёта.

## Структура

```text
log_analyzer/
  api/           REST API и фоновые запуски
  ingestion/     адаптеры входных форматов
  processing/    нормализация, шаблоны, группы и окна
  features/      схема и векторы признаков
  knowledge/     YAML-правила и контур правил
  models/        Isolation Forest и артефакты моделей
  arbitration/   таблица решений и построение инцидентов
  storage/       ORM и сериализация
  services/      сквозной конвейер
  web/           загрузка журналов, сводка и карточки инцидентов
configs/         версионируемая база знаний
samples/         фиксированные журналы
tests/          модульные, интеграционные и сквозные проверки
```

Статистическая оценка не трактуется как предметная причина. При недостатке наблюдений окно получает состояние `insufficient_data`; при недоступности модели контур правил продолжает работу, а ограничение фиксируется в запуске.
